## Execute

1. Clone/check out latest PR #3 branch head on the owner's Windows 11 RTX 5060 PC, isolated from other PRs. Run `scripts/check_gui_design.ps1`, `scripts/check_gui_slice2.ps1`, `dotnet build LocalClip.slnx -c Release --warnaserror`, `scripts/run_tests.ps1`, and `scripts/run_tests.ps1 -Hardware`. Inspect WPF + MinGW CI results. Repair and retest any build/UX defects; push well-scoped fixes to PR #3 and update evidence.
2. Launch normally and with `--minimized` from a rebuilt portable package. Verify full Flick logo in navigation and tray, two functioning nav actions, source picker, refresh, status pill, Start Replay, Save Last N Seconds and the old gallery/trim/audio/export and Discord drag/copy still work. No icon should be replaced by a nested circle. Opening Settings while armed should not stop recording. A source change while armed must show confirmation and a rejected change must preserve the buffered source.
3. Verify notifications with **both toggles ON** (default): save a real 30s game replay, wait for native file finalization and validated library registration; only then show a Flick-branded **Clip Saved** toast (correct actual clip title/duration) and short quiet confirmation chime. Saving a clip must not automatically switch away from an existing clip being edited. Verify notification appears ~2 seconds, no extra full-width bar, no nested badge, no unbounded queue/stack and no persistent overlay HWND/process after dismissal.
4. Verify all four combinations of independently persisted preferences: Overlay ON/Sound ON, ON/OFF, OFF/ON, OFF/OFF. Preview Notification is user-initiated and should not save settings or arm capture. Cancel must discard unsaved toggle changes; Restore Defaults should stage both toggles ON without deleting clips. Restart Flick and confirm persisted behavior. Set the checkbox options while replay is running and confirm no unexpected stop. Validate a failed save displays an error, never success/success sound.
5. Explicitly verify focus safety: play in normal desktop, borderless fullscreen and exclusive fullscreen (exclusive may BLOCK the overlay), press Save hotkey, confirm gaming keyboard and mouse stay focused, overlay stays click-through, no taskbar button/Alt+Tab surface, overlay disappears. Check active game monitor (not necessarily Flick monitor), Windows 100/125/150/200% scaling and mixed-DPI multi-monitor positions; never assume the Win32 coordinates work on all displays. Confirm banner appears within active display bounds and never blocks HUD controls persistently.
6. Repeat 50 hotkey save operations and short-error bursts. Verify one coalesced temporary surface, no lingering timer/window/handle count slope. Minimize/close Flick while replay is active and confirm tray Start/Stop/Save and text/enabled statuses. Quit Flick and confirm notification assets, hotkeys and owned capture hosts clean up. Verify Windows startup preference keeps capture DISARMED. Check chime audibility with system-loopback and whether it appears in subsequent replay; report honestly.
7. Measure capture performance (same scene, same replay settings) with notification feature disabled versus enabled: process RAM/private bytes (working set separate), CPU/GPU/VRAM, avg FPS, 1% lows, p95/p99 frametimes and any hitch at the toast moment. Use owner baseline 48.2 MiB idle app and 142.5 MiB app+host buffering as historical comparison only. Target incremental hidden overlay ≤2 MiB, during toast ≤15 MiB and <1% avg FPS impact; if failing, prefer removing blur while keeping brand/full logo. Confirm there is no additional always-running process/renderer. Test high contrast, transparency disabled and reduced-motion mode.
8. Capture actual screenshots of the shell and notification at 100/125/150/200% DPI and at minimum 1000×650 DIPs and normal 1240×760 DIPs. Check control alignment, Title Case, spacing, accessible names/keyboard navigation, clipping, horizontal overflow, ComboBox popup alignment, tray menus and subtitle readability. Shell correctness isn't proved merely by unit tests.
9. Preserve existing libobs/FFmpeg backend, clips, user settings and the private repo. Do not post to Discord, inject into games, change drivers, reboot, kill unrelated apps, merge PRs or publish GitHub releases without owner consent.
